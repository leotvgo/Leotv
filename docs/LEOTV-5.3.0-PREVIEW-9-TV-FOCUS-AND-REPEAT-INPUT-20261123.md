# 5.3.0-preview.9 / 621：TV 实际焦点、确认编辑与重复扫码

用户在 preview.8 交付期间继续报告 TV 搜索输入、默认焦点、视觉顺序、API 设置焦点、原生菜单新增控件及重复扫码问题，并补充详情页首次确认不能播放。本轮一并修复，保留 preview.8 手机原生细外框及 TV 搜索透明度。

## 搜索输入与方向键

仅关闭 showSoftInputOnFocus 未能满足设备行为。TV 搜索现在使用确认式 EditText：浏览状态没有 KeyListener，inputType 为 TYPE_NULL，onCheckIsTextEditor 返回 false，onCreateInputConnection 返回 null；焦点经过时仍能高亮，但不提供编辑连接。确认键/点击恢复真实编辑属性，并 restartInput/showSoftInput；搜索、离开字段或输入法返回后回到浏览状态。手机继续普通 EditText。

各可聚焦 View 都生成 ID，并显式设置四向目标；方向键按这些连接处理：

- 输入框向右是二维码，再右是搜索；搜索向上是接口设置，接口设置向下是搜索，再向下是集数排序。
- 输入框向下直接进入来源分类；排序向下也是来源分类。
- 来源分类之间左右移动，向下进入作品分组，再进入选集网格。
- 作品头、目录加载入口及网格每行按实际绘制顺序记录；网格上下在相邻行按列对齐，第一行向上返回对应作品头，不跳过分组。

打开搜索窗口时保留已加载目录，按当前已选择的弹幕 URL 定位来源、作品和剧集，布局完成后让实际剧集 View 获得焦点。不再无条件重搜并把焦点固定到输入框。目录仍在加载时等待实际剧集；用户开始移动或手动搜索后停止默认焦点接管。

## 设置列表与原生菜单

TV API 设置把 ListView 的行选择改为实际可聚焦的原生样式 TextView 行：白色描边、黄色焦点文字，上下顺序明确，初始选中第一项。手机列表保持。

用户随后要求设置入口不要沿用播放器的半透明面板。现在按入口区分：播放器/弹幕搜索调用带会话的设置，保留半透明自定义面板；个性设置或原生设置页调用不带会话的设置，使用原 Material 设置弹窗、原标题和取消按钮，列表仍无单选圆圈。两者共用同一份 API/策略设置。

TV 原生弹幕菜单的新增放大镜沿用原文件夹 ImageView 的布局参数、padding 和 selector_image，恢复原 wrap-content 的约 32dp 控件范围，不再固定 44dp。新增开关的文字与 Switch 分开，Switch 沿用同一白色轮廓 selector，并与新增搜索图标互相连好左右焦点。开关行为和原弹幕按钮点击/长按、上下调延迟保持。

## 同一扫码页面多次输入

旧网页成功后清空 token 且保持按钮禁用；旧电视绑定又随着二维码窗口关闭而清空。现在二维码使用当前 APK 进程内复用的配对标识，网页提交完成后重新启用按钮，成功仅清空输入内容，保留配对。

电视输入目标改为最多 16 个弱引用绑定，按当前前台输入窗口/字段选目标。原生单字段输入、TMDB Key/域名、对应扫码按钮与 TV 搜索注册目标。二维码窗口关闭不会结束仍可用的外层字段；窗口关闭或 Activity 销毁的目标被移除，并可返回下层有效输入窗口。打开其它配置或选中另一个字段后，原手机扫码页可以继续提交，无需重新扫描。应用进程重启后的配对需重新建立。

回填仍在主线程执行，入队后再次确认目标归属；原 `do=setting` 线路保持独立。没有有效前台输入字段时提示在电视打开输入窗口，不把这种情况要求为重新扫码。用户输入、Key 和凭据不回传网页、不写日志、不保存到 Git。

## 详情页首次播放

原首帧可能把焦点交给可聚焦的海报容器，加载/主题布局完成后没有接回真实播放键。TV 海报容器现在不作为焦点目标；首次布局和加载布局变化时，在用户尚未交互的阶段将焦点交给真实播放按钮。首个确认键也先核对该目标，随后交由原点击处理。用户开始按键或触摸后停止默认聚焦，不持续抢走其它控件焦点。续播、片源及播放条件继续走原按钮回调。

## 构建边界

普通 smali、数据库和原 ZIP 资源没有新增修改。程序修改限定在搜索/控件/设置/原生输入桥及详情焦点；TV `assets/index.html` 的变化仍由固定摘要与三处插入门禁管理，本轮更新其中的扫码提交脚本。Android 6、两个 ABI 和手机/TV 区别保持。
