# 5.2.9 / 629：TV 原生返回顺序与播放返回焦点

用户报告 TV 全屏唤醒控制栏后按返回直接退出播放，回详情后的实际遥控焦点也没有落在当前剧集缩略图。用户强调全屏交互应保持原生：控制栏显示时先收起，再返回才离开播放；回详情聚焦最新播放的剧集，包含播放器内换集后的当前项。

## 三版比较和归因边界

对 5.2.6、5.2.7、5.2.8 对应 Git 源码比较，`Playback.leave`、原返回挂接、`TvDetailNavigation` 和 `TvDetailPage.resume` 的摘要分别完全相同。已保存在 `evidence/leotv-tv-back-and-playback-focus-comparison-20261124.json`。

5.2.7 的在播样式变化仅将 activated 项改为黄色文字、白框改为实际焦点条件，未处理返回键或 requestFocus。旧样式合并了播放激活与遥控焦点的白框，不能用旧白框证明实际焦点跟随。详情 resume 刷新 History 与在播标记、重建选集，却未将实际焦点交给最新剧集，导航书签仍可保留上次遥控项。样式分开后这一差异更明显。

直接退出的明确源码问题是旧 `Playback.leave` 在独立播放器上无条件 `finish()`；返回挂接放在 TV 原 `VideoActivity.s()` 的入口，跳过了原第一段控制栏隐藏和第二段原附加面板关闭。该挂接在 5.2.6 也存在。源码比较不能证明用户设备上为何 5.2.6 未触发同样症状，因此不将其记成 5.2.7/5.2.8 新增的返回键修改，也不否定用户真机反馈。

## 全屏返回修复

移走 TV 方法入口的提前退出。原 `s()` 控制栏 → 附加面板两段完整代码先执行，只有原生进入实际退出/折回小窗的决定位置，才将独立播放器交给已有 `Playback.leave` 离开 Activity。普通宿主的原折回小窗/退出逻辑保持，手机原返回路径保持。

没有另写控制栏显隐判断或遥控派发函数。原 native `dispatchKeyEvent`、按键辅助类、`o0/n0` 控制栏/面板关闭方法、遥控方向、快进、暂停和原弹窗路径均保持。保留现有弹幕接口、控件及播放器协议。

## 返回详情的当前剧集焦点

APK 详情发起 TV 全屏播放前记录一次返回标记，包含父 Activity 被恢复的保存状态。回到详情时读取原最新 History/播放 checkpoint，先更新真实当前线路与剧集；启动专用于这次返回的焦点定位，不影响首次进入详情的默认播放按钮。

等待详情窗口、实时选集布局和实际目标尺寸就绪，在当前线路中找到已按播放身份激活的真实剧集 View，更新原导航书签并 requestFocus，水平显示缩略图、垂直显露对应选集区域。异步元数据/布局重建期间重新找到活 View；已定位的同一个 View 不反复触发滚动。第一次用户按下/触摸或页面暂停后结束自动定位，后续导航由用户控制。

恢复后的在播黄色文字与实际焦点白框会落到同一当前播放资源；随后用户移动焦点时仍区分二者。详情自身“返回先回顶聚焦播放按钮，再返回退出”的 5.2.6 规则保持。手机不执行本次自动焦点定位。

## 允许变化和门禁

新增生产源码修改仅为已有 `DetailActivity` 与 `TvDetailPage`，以及 TV 原 `VideoActivity.s()` 的已有退出挂接位置。无新增生产类、布局/图片资源、数据库、JNI/反射接口、回移层或原生/ZIP 资产；5.2.7/5.2.8 的 TMDB、弹幕和样式修复保留。

`tools/check_build_sources.py` 新增 TV 强制核对：四变体按实际顺序挂接后，TV 原 `dispatchKeyEvent` 方法完整文本一致；`s()` 原控制栏/面板前缀和原退出尾部完整一致，唯一 APK 退出调用位于两段原面板判断之后。原 smali 固定摘要、API/源码路径、R8 stable ABI、原样/允许变化审计和固定签名核对照常。

版本 stable 5.2.9 / 629，R8 8.8.34 release/full、min-api 23、固定 APK 签名和 TV/手机双 ABI。按用户既有要求不运行本地打包或额外回归，直接 GitHub `run_validation_tests=false`；必要源码、编译和签名门禁保留。原生 Back 实际优先级、播放器内换集后回详情的焦点/滚动，由用户签名后真机验收。推送构建前临时公开，发布成功后恢复私有并核对。
