# 5.3.2 / 643：新增缓存接入原生清理策略

用户确认 642 体验稳定，明确授权统一接入新增缓存清理，要求保持稳定操作体验，并进一步要求尽量沿用原生清理策略。前置排查见 [642 缓存清理报告](LEOTV-5.3.2-CACHE-CLEAR-REVIEW-20261125.md)。

## 原生策略保持

TV `S3/d.run()` 与手机 `U3/g.run()` 的 cache 分支仍使用各端原方法获取应用 `cache` 根并递归删除，原订阅 `Config.json("").save()` 缓存副本复位与缓存大小刷新回调保持。新增代码只包裹原删除调用；正常完成与原删除抛异常时均调用清理结束方法，原异常继续抛出。备份、恢复、其他分支、字段、构造与注解不修改。

必需门禁核对：去掉这一段包裹后，两个工作类在四变体中的完整源码与原字节逐字节一致。原 `bytecode-project` 不修改，包裹在专用构建的已声明源码变更清单中应用。

保留原设置入口、后台删除、系统缓存目录、原回调和页面实例；不重启应用、不重建页面、不重新绑定当前海报或焦点。数据库 schema/migration、订阅地址、Key/Cookie、设置、追更、手动匹配、历史/收藏、下载和媒体数据保持原协议。

## 写入与内存协调

- 新增 `CacheMaintenance`，由原 Application 的 `GlobalChrome.install` 安装。原清理工作线程先等待已经进入写入阶段的缓存完成，递增清理代次并暂停新增缓存写入，清空可丢弃的元数据、详情会话、排期、评论答案及预取登记，再执行原删除。结束后重置图片缓存计数/代次并恢复后续写入。多次清理在原工作线程上串行，不阻塞主线程等待。
- 正常文件写入使用共享许可，图片、元数据、弹幕仍可并行，保持各模块原有锁和线程数；清理边界使用排他许可。生产者无法取得许可时放弃缓存写入，仍按原显示链路处理结果。
- `BackdropHttp.Request` 保存清理代次，子请求沿用父代次。元数据 JSON、自动匹配、首页快照、详情返回缓存、排期答案、图片编码与弹幕文件写入携带原代次；旧结果不能在删除后重新填回这些缓存。共享任务的完成回调按任务对象身份移除，避免旧任务误删新请求登记。
- 当前可见请求保持，不把清理代次变化当作页面/网络取消。图片结果可完成当前显示，但过期结果不重新进入图片缓存。弹幕清理保留播放器已有评论和渲染状态；清理前仍在生成的 API XML 不写回、不接管当前弹幕、不弹出过期错误提示。清理后的新操作按原加载逻辑重新缓存。
- 轮播只释放每张 Slide 的编码 bytes，当前/下一张已解码图片、入场/切换动画和待处理遥控动作保持。缩略图清理释放缓存引用和远处等待队列，取消未绑定的投机任务；View 已持有的位图不直接 recycle、不主动清空 drawable，不改变滚动/焦点。正在显示的页面资料继续保留；正常离开/返回按原生命周期处理。
- 系统 `onTrimMemory/onLowMemory` 在独立有界后台任务中清空可丢弃答案，再向主线程发送轻量图片引用清理。普通 `TRIM_MEMORY_UI_HIDDEN` 不触发，正常切到设置/播放/后台不因此丢失缓存。100MiB 缩略图预算与现有缓存上限保持。
- DNS、网络路线、连接池及客户端、原历史数据库与最新播放快照保留，避免额外连接重建、路线复测或续播进度变化。它们仍使用原有数量/时限边界。

## 图片存储

`DetailHero` 的 TMDB w1280 图片改为与 `TmdbArtwork` 预取使用同一磁盘 key，避免同一高清图片在首页、详情和预取层重复写入。站点自定义请求头/参数仍保留原 source key，缩略图不同 rendition 仍各自存储。大多数原 w1280 图已有预取 key，可直接读取；旧副本留在原 cache 下按原清除/预算淘汰，不对用户文件额外清理。

## 范围与门禁

新增一个生产协调类，修改 14 份已有 runtime 源码及 Application 现有安装点，其他 **88 份 runtime Java** 与已交付 642 逐字节相同。元数据加载阶段、线程数、API/图片地址、主备路线、TLS、持久缓存大小/TTL、TV 首屏/遥控/布局和主题保持。精确清单见 `evidence/leotv-5.3.2-643-cache-source-scope-20261125.json`。

新协调入口加入 R8 固定 ABI 声明与 keep 规则，原清理工作类加入四变体锁定路径及允许变更审计。`check_cache_maintenance.py` 接入必须源码门禁，钉住原策略、正常/异常结束、旧写入隔离、共享任务身份移除、弱引用图片清理和当前画面保护。

版本名保持 **5.3.2**，内部版本码升至 **643**，继续四套固定签名 APK。按既有要求不做本地 APK 打包或额外回归；GitHub `run_validation_tests=false`，保留必需源码/API23/R8、原样/允许变化和固定签名核对。实际清理大小、内存释放、轮播、遥控/触摸和播放/续播仍由用户真机验收，当前 View/播放器持有的数据保留不等于进程内存立即归零。

新四套包成功后，旧 642 的四套 APK 和八份报告完整归档为内部草稿，再替换同版本正式下载。沿用此前已授权的临时公开构建流程，完成后恢复并核对私有；交付记录见 `evidence/leotv-5.3.2-643-build-dispatch-20261125.json`。
