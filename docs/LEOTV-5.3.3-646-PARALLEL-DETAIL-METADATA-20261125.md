# 5.3.3 / 646：入口/历史详情元数据并行加载

用户初步确认645的弹幕识别与自动应用可用，随后反馈TMDB轮播可能较慢，要求排查新资源和历史记录是否等待站点或播放链接解析，并在有效标题就绪时启动整套元数据/海报流程。用户指定本轮版本名称5.3.3，撤下旧5.3.3与5.3.4；内部代码升到646，保持覆盖升级645的能力。

## 发现与范围

普通资源与历史记录在没有会话缓存或元数据入口种子时，`DetailActivity.load()` 原先先调用 `SourceGateway.load()`，收到站点详情才调用 `enrich()`。这个顺序在645之前已经存在，不是645四项优化新增的等待。原生任务调用站点 `detailContent`；播放器播放URL解析属于进入全屏播放后的原链路，不是新元数据任务的启动条件。

645的新缓存预算作用于缩略图加载器，详情轮播仍由DetailHero/TmdbArtwork独立加载；减少远处预取可能影响快速翻到远处图片的热度，本轮没有通过实测速率证明它导致首张详情海报变慢，因此保留已授权的645优化。

本轮仅修改4份runtime源码：DetailActivity、TvDetailPage、SourceGateway、NativeLibrary。其余104份runtime源码与645逐字节相同；精确摘要见 `evidence/leotv-5.3.3-646-source-scope-20261125.json`。

## 最终加载行为

- 普通入口先读取原入口标题、海报、年份与类型；标题缺失时，仅查询当前订阅/站点/资源对应History的getVodName，不读取或解析播放链接。没有有效标题则等待站点首次给出标题，随后立即启动元数据。
- 有有效影视标题时先挂载临时资料并启动TMDB渐进详情与轮播，再提交原站点详情任务。元数据使用独立执行器，不被站点任务或其积压占用。
- 临时资料不启动自动站点搜索、不写入可播放会话缓存或发布未就绪的来源信息。站点失败也不取消已经启动的元数据；实际播放仍等待原站点/剧集数据。
- 站点返回后接入原播放分组、历史续播与排序，保留已经显示或加载中的TMDB图片。没有TMDB图片时继续保留站点原图回退。补充的年份/类型确有变化时才进一步校正匹配，相同证据复用当前任务。
- 站点回调只验证其来源代次；元数据刷新不再使仍有效的站点响应被误丢弃。退出页面仍取消两套任务，原缓存/配置变化边界保持。
- 已有完整会话缓存时直接恢复元数据/轮播，避免先发起站点图片再切回缓存TMDB图片。追更、相关作品、索引元数据种子的原有快速入口保持。

原645的弹幕标题清理、详情集数优先、手选目录换集、匹配消歧、数据协议、内存清理、图片预算、预取窗口、网络路由/退避、字符串保护与固定签名保持。

## 仓库可见性问题

用户明确限定“公开期间没有任何外部克隆/fork/复制，只考虑GitHub自身编译缓存”。正常权限控制下，恢复私有后，无权限的新请求不能仅凭旧提交SHA、构建或缓存编号读取私有源码。当前未携带GitHub登录凭据的核对结果为：源码/提交/缓存入口404，构建日志入口403，没有取得内容。这只证明这次入口访问结果，不证明全部内部缓存被删除。

[GitHub官方说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)另外明确指出，若公开期间存在public fork，改私有会将它脱离为新网络而不将fork私有化；这不属于用户已排除副本/fork的前提。本轮未声称公开窗口没有被外部抓取，也未以恢复私有声称收回副本。

最终构建、归档、正式发布、资产核对与私有恢复记录将在本轮交付evidence补充。加载速度与真实电视/手机表现由用户安装646后验收。
