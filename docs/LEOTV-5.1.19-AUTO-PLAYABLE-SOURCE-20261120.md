# Leotv 5.1.19 元数据条目的自动播放资源

用户反馈 JAR 豆瓣条目没有自身播放数据，壳详情能异步搜索但只能手动打开站点选择结果。原 `DetailSiteSearch.Listener.changed` 仅刷新菜单，没有自动解析/采用候选。

- 手机/TV 共用逻辑：当前详情无 flag/episode 数据、没有手动选站或当前配置的保存历史时，开启自动找源。已有播放数据/历史或手动选站只更新搜索菜单，不自动替换。
- 保留现有搜索可用性及名称/年份/类型/季号筛选，按站点搜索完成顺序逐个调用原详情任务解析完整播放数据。当前元数据站点、目录项、空详情/失败/无剧集跳过；完整详情已知年份/类型/季号不一致或音乐源不匹配时跳过。
- 自动采用已解析详情，直接填入原线路/选集区，无需再次请求详情或手动打开站点菜单。原生播放解析仍由用户点击播放或剧集后运行；已有丰富海报/标题/元数据保留，不为找源丢弃已匹配资料。
- 候选解析为后台有界线程池，单候选45秒超时；搜索 generation 和 selection generation 共同拒绝迟到结果。换源、手动选择、重搜和销毁取消旧任务。站点菜单打开时保留待采用结果，关闭后才采用；手动选择始终取消自动模式。
- 用“正在寻找播放资源/获取播放线路”提示进度，耗尽候选后保留手动站点入口。采用后等待新视图布局再绘制，避免未测量的选集短暂显示。

版本 5.1.19 / 529。只改变声明的详情覆盖类和版本资源，V6 核心继续使用 v6.2026.11.20.2。按用户既有直接构建/真机验收方式跳过本地/CI回归套件，GitHub 执行 API23 编译、原样/允许变更审计、固定签名和发布；真实线路的可播放性和设备体验由用户复测，不将存在剧集数据等同于媒体已成功播放。
