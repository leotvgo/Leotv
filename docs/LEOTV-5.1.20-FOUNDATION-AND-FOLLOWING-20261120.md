# Leotv 5.1.20 基础功能与追更日历

本轮交付版本 5.1.20 / 530，保留手机/TV、ARM32/ARM64 和 Android 6（API23）。配套 V6 继续使用 v6.2026.11.20.2，本轮没有修改或发布 coos 核心。

## 手机顶栏折叠

上沿内容扩展时此前取消了父层裁剪，导致原 AppBar 折叠后的控件仍能从系统状态栏后露出。现在随原 AppBar 的屏幕位置更新局部裁剪，控件到原生状态栏下沿即消失；原生嵌套滚动与折叠行为保持。退出内容页恢复借用前的裁剪、层次和背景，保留内容在原生状态栏下滚出及顶端淡出。

## 找源、播放与详情缓存

- 无播放数据时统一显示“正在加载…”。站点搜索并发由8升到16，完整详情候选解析由2升到4，并允许4个候选同时解析。首个匹配且有剧集的结果胜出；菜单打开时保留首个结果，手动选站、换源、销毁仍取消旧结果，单候选45秒超时。
- 将已获取的原生 Result 完整 JSON 一次性交给原播放详情任务，校验配置、站点、资源ID及15秒有效期。只覆盖原任务 discriminator=0 的详情分支；没有可用缓存则走原路径。减少点播放后重复请求线路详情的等待，保留原生解析、暂停和播放器控制行为。网络解析等待仍取决于站点。
- 详情加入12条有界、不保存解码海报的内存缓存，并保护当前播放资源。缓存键包含配置、站点、资源、元数据设置和显式匹配；追更变更不会单独令缓存失效。成功资料不被失败刷新覆盖；源和资料身份不一致时不写入旧资料。
- 保存当前选中资源的实例状态，方向/尺寸变化由详情页重排，返回播放后复用资料。进程被系统终止后仍需重新获取资料；本轮缓存不是跨进程永久缓存。

## 追更入口与两端日历

- 手机在原生底部导航第二位加入“追更”，其余三个按钮保留原入口及原生图标着色/布局。
- TV 在首页首个分类按左键显示屏幕左侧居中的日历按钮，默认隐藏，焦点自动落到按钮上，确认进入日历。右键/返回关闭入口并恢复先前焦点，离开首页/首分类时隐藏。
- 从 JAR 移植日程获取、日期条、月份选择器和日历页。手机沿用单列卡片与原生日期弹窗；TV 沿用横屏网格、日期焦点、遥控月份选择器及卡片导航，不把手机布局拉伸到电视。
- 壳与 JAR 使用同一应用的 `leo_following/entries` 及相同 schema。详情优先调用 JAR 追更桥，未注册时写入壳本地库；不能各自 toggle 一次，否则同一条目会立即被取消。
- 日历卡片长按或“管理 → 删除追更”使用幂等删除；管理入口也可打开条目详情。壳日历和详情监听追更库变更；JAR HomeUi 在返回时重绘追更。删除最后一个条目后清空旧日程，空列表管理显示提示。

## 变更范围与验证边界

声明的新增覆盖类位于 `detail/runtime-sources.json`；全局导航/折叠位于 GlobalChrome。原生修改范围与 SHA256 固定在 `detail/native-source-lock.json`，新增手机 E3/n、TV B3/n 的详情任务入口，保留其余分支。Manifest 新增 FollowingActivity，详情与日历登记方向/尺寸配置变化；版本资源更新。原数据库 migration、JNI/反射 ABI、原 native 资产、j$/java.util.function 回移层保持。

本地已完成 API23 javac、D8 与允许新增类导入检查、四变体原生契约审计。按用户直接真机验收要求，不运行回归套件或 Android6模拟器；GitHub 仍执行必要编译、原样与允许变化审计、固定APK签名及发布。手机顶栏触摸折叠、真实搜索/播放、返回缓存、手机/TV日历布局和遥控快捷键，以签名产物真机复测为准。

MPV 调研报告和固定来源/ELF证据一并保留，仅作后续接入参考；本轮未引入MPV库。
