## 四项加载与内存优化

1. **基础资料与可靠 ID复用**：成功的实际作品详情响应保存按类型/ID/配置隔离的有界轻量快照。已知身份先发布其中基础字段；新鲜且包含完整 images 集合时，首页可复用结果。详情继续加载演员、推荐、评论、视频、季/集等所有现有模块，同名消歧与手动选择保持。读取旧匹配不延长实体新鲜期。
2. **图片请求去重与预取范围**：相同 URL/代理/代次/下载限额共享 FutureTask 与编码图片磁盘键，跨缩略图加载器复用；不同尺寸保持独立 rendition。保留旧缓存读取和站点自定义请求协议。首页预取前3个候选，轮播随当前项预取当前及邻近两项；离开/替换时只取消无人需要的排队预取，正在运行或已有前台读者的共享任务继续。
3. **刷新冷却、429与网络状态**：失败刷新按键/缓存代次/网络代次记录有界冷却，旧缓存仍可立即显示；成功、原生清理和网络切换复位。支持 Retry-After 秒数与HTTP日期，429默认20秒、上限24小时，内置别名和代理路线共享同服务限流；取消备用竞速，避免重复放大。网络身份变化清除旧DNS、路线与失败状态，旧DNS任务不回填新代次；保留连接池和既有客户端。
4. **设备共享图片缓存预算**：按应用最大堆与 memoryClass 的较小值约1/8计算，8–100MiB，low-RAM设备最高24MiB；多个缩略图加载器共同计费。预算满时仍向当前View交付图片，仅停止额外缓存；不回收View正在使用的像素。现有内存压力回调、磁盘500MB默认、轮播current/next和原生播放器保持。缓存预算不等于全进程PSS，低内存设备可能更多读取磁盘/重新解码。

## 加固与公开审计

新增 Java 字节码进入固定 R8 前，对选中ASCII端点、DNS/缓存/内部标记及内置32位十六进制常量进行 AES-128-CTR 字符串保护，运行时按常量缓存解码结果。字段初始值与LDC引用一起转换；编译工具核对每项往返，再核对新增DEX的所有字符串中没有选中明文。用户文案、协议实际值和外部ABI保持。

R8沿用8.8.34 release/full/API23，用无语义ASCII字典混淆内部类与成员；保留稳定Activity、JAR/JNI、反射、序列化和回移契约。构建私有种子随mapping内部归档，不进入Git、日志或公开资产。字符串保护增加静态分析成本，不等于不可提取的客户端密钥保护；未引入敏感词诱导字典、全包壳或阻断式反调试。

四变体完整源码/原样/变化审计与mapping进入内部符号草稿，之后才生成公开审计摘要；摘要按SHA-256绑定完整报告，不公开源码路径、Smali改动清单或宿主重优化策略字段。APK专用固定签名及原生资产核对保持。构建与发布步骤仍核对必须审计，不能通过生成摘要绕过检查。
