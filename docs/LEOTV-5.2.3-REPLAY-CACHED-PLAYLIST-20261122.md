# Leotv 5.2.3 / 612：详情返回后再次播放黑屏

用户报告详情点击播放正常，返回后按钮显示续播进度，但再次续播或选另一集均黑屏，播放器内播放/刷新无效；随后明确要求确认后直接修复、推送编译正式版本，不再测试。

原详情缓存保留已经初始化的 Result/Vod/Flag/Episode，同一份对象跨播放器 Activity 使用。TV 的 `O0(Flag,ZZ)` 与手机的 `w0(Flag,ZZ)` 遇到 `Flag.isActivated()` 为真直接返回，跳过剧集适配器绑定。第一次播放会修改这些缓存对象的激活状态，第二次交接没有清除；即使选择同线路的另一集，也会留下空剧集适配器。原 `A0()` 的播放/刷新分支因适配器为空返回，不能重新请求播放源。切换到未激活线路可能暂时可用，下一次该线路同样受影响。

`Playback.consumeNativeDetail` 在站点、资源、配置、时限及一次性消费校验后，交给原结果控制器前，将各 Flag 的私有 `activated` 清为 false，并通过原公开接口清除 Episode 的 `activated/selected`。保留同一初始化结果、剧集 URL/顺序和其它协议数据，续播位置仍由原 History/播放器控制；不进行 Result JSON 往返，不写数据库。如果重置接口不可用，返回 null，回退原详情任务重新加载。

允许源码变化限定于 Playback、编译期 ABI 门禁及测试夹具/用例、版本声明和本记录。四变体原 Flag 私有字段加入 ABI 检查；原 smali、数据库 schema/migration、JAR/JNI、回移层、各 ABI native 与 ZIP 资产沿用门禁。

用户要求停止测试前已启动的虚构夹具检查完成，旧代码在同集/同线路换集第二次、换线路第三次没有派发播放请求，与原 smali 分支吻合。保留连续四次交接的回归用例及更接近原生激活分支的夹具；修复后按用户要求不继续执行测试，不将这份旧代码复现记录当作修复后的通过报告。当前 ADB 无连接设备，未作真机验收。

正式版本 5.2.3 / 612，stable、非预发行、发布后设为 Latest。GitHub 使用 `run_validation_tests=false`，仅执行必要的 API 23 编译、R8 8.8.34 release/full、原样/允许变化和既有固定证书签名门禁，提供 TV/手机与 32/64 位四个包。V6 核心不改。
