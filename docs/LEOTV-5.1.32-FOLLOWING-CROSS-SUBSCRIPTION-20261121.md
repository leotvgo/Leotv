# Leotv 5.1.32 / 542：跨订阅追更找源

用户定位到具体触发：在嗷呜订阅下添加追更，随后切换到自有 JAR，APK 追更日历仍显示旧条目；点击时把添加时的 site/id 交给当前 JAR 的 detailContent，当前 JAR 无法解析旧 ID，于是停在“线路详情暂不可用”，后续跨站搜索也没有启动。

日历卡片和“管理 → 打开详情”共用的 opener 现在传入只读、按原 site/id 绑定的标题/年份/类型/图片/TMDB 元数据 Bundle。详情页优先按这个作品快照进入元数据详情，不请求旧 ID、不借用旧站点详情缓存，也不以旧播放历史阻止自动找源。追更记录与添加时间原样保留，不迁移或覆写用户数据库/配置。

这个 metadata-only 来源开启 searchCurrentSite。搜索仍使用当前宿主配置及既有搜索可用性、名称/年份/类型/季号过滤，但不把与原条目同 key 的当前线路直接视为“已有结果”，而是实际搜索并解析当前候选。解析到带剧集的匹配资源后，继续通过原 automaticSource 填入实际站点和选集；用户手动选站、已有真实剧集详情及普通资源入口保持原规则。

手动或自动换源时移除日历快照标记，防止同 site/id 的新候选在旋转或再次加载时又落回旧追更快照。快照本身还校验 Intent site/id，防止错绑其他资源。原详情主题、元数据匹配、收藏、下载、播放器和续播链路保留。

允许变化类为 FollowingActivity、DetailActivity、SourceGateway$Detail、TvDetailPage、DetailSiteSearch；不新增生产类、不改原 smali、布局或 native。版本元数据更新 5.1.32 / 542。用户要求直接构建、真机验收；本轮不运行本地测试，GitHub 使用 run_validation_tests=false，保留 API 23 编译、原样/变化审计、四变体固定签名。

手机 JAR“我的追更”界面的重叠另由 V6 核心修正，只在手机 com.leotv.app 内适配 JAR 自己的整页容器，不桥接该入口到 APK 日历，保持冲顶与上下透明栏下的滚动；APK 本轮不修改首页容器或栏位绘制。
