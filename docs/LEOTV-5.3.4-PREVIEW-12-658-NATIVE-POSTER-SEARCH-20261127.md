# 5.3.4-preview.12 / 658 新主页海报原生长按全局搜索

用户明确要求把原 OK 影视的资源海报长按动作接到新主页及全部新主页分类，并明确在 Tg 豆瓣首次自动找源原因无法确认时优先完成该入口。

## 实现范围

- 原普通 TV 的 P3.e/P3.f 资源长按使用 Vod.getName → CollectActivity.V，手机 S3.z.v 使用 Vod.getName → SearchActivity.S。这两个长按入口不检查站点 indexs/changeable；TV 原方法带 FLAG_ACTIVITY_NEW_TASK，手机保持当前任务。
- 新 PosterSearch 复用同样的原生目标、完整关键词和任务标志。仅设置 OnLongClickListener，动作直接进入原生全局搜索，不先调用原站详情/播放器，不读取站点 indexs/changeable 或额外开启条件。原生全局搜索目标站点仍遵循用户原来的搜索启用配置。
- 新主页轮播使用当前显示条目；分类、推荐/更多的自绘海报通过共用 NativeCspUi.bindCard 接入，异常重试卡片也能长按。TV 普通分类原生页面原有长按继续保留；回收卡片和轮播关闭时释放新增长按监听。目录/操作条目保留原生长按排除规则，历史卡片沿用其原生长按操作。
- 手机轮播原 GestureDetector 禁用了 longPress 且触摸回调截获事件，补回标准长按识别；长按后抬手不再触发短按进入详情/播放，左右滑动和上下滚动保持。
- 仅增加事件接线，首页分类边距、卡片尺寸、布局/导航、详情演员与主题、播放器及弹幕不修改。652 回退源码身份门禁只剥离两处明确授权的长按接线行，仍核对 23 个恢复块；不改旧源码基准散列。

## Tg 豆瓣排查边界

实际订阅中的该站点没有 indexs 字段，searchable=1、changeable=0。首次详情页无可播放剧集、站点菜单无结果，手动重新搜索可以出结果；这证明自主搜索链路能工作，但尚未拿到其受保护 JAR 的实际详情返回，不能确认是返回的中间播放数据、首次关键词或触发时序。按用户最新要求，本版先接通独立长按入口，不按猜测改动自动找源/资源判定，也不修改第三方订阅、JAR、代理或凭据。长按入口独立于这家站点的原生点击行为。

## 必需核对

GitHub 增加实际 API23 事件检查：长按进入原生全局搜索且不触发资源短按、两端原生任务标志和完整关键词、轮播/回收条目更新、无效条目与监听释放、生产手机轮播触摸处理长按后抬手消费。手机触摸方法从当前生产源码原样抽取，使用实际 GestureDetector/View；不作为真实设备或 CSP 查询验收。

原源码/恢复布局、原样/允许变化、固定 native/原 ZIP、API23/R8/JNI 与固定 APK 签名审计保持；不做本地 APK 构建。新增类/事件源码通过 integration-649 的 authorized_658_source_repairs 追加记录，私有订阅数据和分析材料不进入 Git 或发布产物。运行行为由用户 TV/手机验收。
