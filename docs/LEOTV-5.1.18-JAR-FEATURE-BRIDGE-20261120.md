# Leotv 5.1.18 全分类背景与 JAR 追更桥

用户确认新主页背景正常，但其他分类顶部仍露出宿主壁纸；希望保留 APK 详情页，仅将追更功能交给 JAR，另反馈 Leo 字幕、Auto 和豆瓣热评未注册。本轮配套 V6 `v6.2026.11.20.2`。

- 淡出先读取当前分类的页面背景，否则读取 content 直属子层中标记 `leotv_shared_backdrop` 的 JAR 宿主背景层。所有分类自动共享正在同步的背景，排除缓存推荐页或子页的背景；当前推荐页轮播协议保持。
- 壳追更原本只有“追更暂未开放”占位逻辑。新增平台 `JarIntegration.register(Object, InvocationHandler)`：已加载 JAR 通过 Activity、操作名称和 Bundle 交换追更状态与公开元数据，JAR 原 `FollowStore` 负责写入、取消和首页日历刷新。壳详情、主题、匹配、收藏、播放仍由 APK 处理。
- 元数据绑定准确的站点 key/资源 id，未匹配时禁止新建追更，已追更资源可取消；换源时不会将上一资源的元数据登记到新 id。剧集总数/季数/播出日期同步到原追更条目，保留添加时间。只传公开影视元数据，不传 TMDB Key、Cookie、令牌、解码图片或播放地址。
- 平台桥使用弱 owner/handler 和弱 Activity 缓存；JAR 晚初始化时重新发布当前资料并刷新按钮，销毁详情时归还。当前资料随播放器 Intent 携带，给 JAR 原 Auto 查询提供已匹配 IMDb，避免因壳详情与 JAR 类模型不同而丢失。
- 核心原宿主准入缺少 `com.leotv.app`；配套核心只接受 APK 已核实的固定证书，再按原播放器 ABI 选择手机/TV。原扩展控制器继续注册 Leo 字幕、Auto、豆瓣热评；不重新接管壳详情或重复绘制壳播放器标题艺术字。

版本 5.1.18 / 528。APK 回归套件按用户既有要求跳过，GitHub 执行 API23 编译、原样/允许变更审计、固定签名及发布。核心桥接/准入专项与完整发布门禁另记；真实手机/TV 的追更日历、播放器按钮与字幕/热评网络行为由用户验收。
