# Leotv 5.3.6 / 664 资源失效提示范围修复

接替中断窗口，落实用户要求：首次点击资源卡片进入详情、元数据预览与自动搜索/自动找源不提示“该资源跑路了 请更换站源”；仅详情内手动切换站点资源，或从原生播放记录/最近观看打开资源，实际完成返回空剧集或空播放地址时提示。版本名继续5.3.6，版本码664用于覆盖升级663，完整/基础、TV/手机、两个ABI共八套产品保持。

## 修复范围

- 原662/663仅判断完成结果是否为空，首次详情返回调用resourceResult、TV首次绑定自动发现路径均可能误弹。详情控制器现在维护当前资源的提示资格；仅原生历史入口或手动换源完成绑定才具备资格。
- 原生TV历史及最近观看两个点击分支位于Q3/a，手机历史点击位于T3/a、继续观看位于R3/F。这四个入口原来都传空mark，不能凭mark或数据库中存在同名历史猜测入口。仅将其原6参数调用转接到openHistory，显式携带来源标记，保留原site/id/name/pic/mark和导航flags。原收藏、资源卡片、目录文件、投屏及推送分支保持原调用。
- 手动请求开始即撤销旧资源资格，完成绑定后允许提示；自动找源绑定清除资格。详情和路径回调同时核对当前资源对象，保留原请求代次、配置核对、超时与取消隔离；旧结果不能弹到新资源。
- 手机层级路径内的失效文字也受同一资格控制，首次/自动阶段沿用普通路径说明；异常与超时继续显示加载失败/重试，不判定为资源失效。内存详情缓存命中与页面状态恢复保留当前入口资格。
- 新增openHistory的稳定ABI并加入R8后原生调用目标核对。原smali文件不修改；固定锁中添加三个历史调用文件，在GitHub按实际有序补丁生成，并列入明确允许的变化类。变更前后摘要记录于player/integration-649.json的authorized_664_source_repairs，663原始摘要继续保留。
- 原启动版本/浅深色适配、TV大图标修复、上层14sp/下层12sp、菜单单选、路径名称/顺序、站点协议、播放器、数据库与用户配置保持。
