# 5.2.6 / 626：TV 新首页跨分类视觉焦点修复

断线窗口最后的用户要求：从热播分类第 3 张卡片按下应进入正下方分类对应位置，上下左右应遵循屏幕视觉位置。此前首页和弹幕设置首次焦点修改已推送，但尚未构建；本次接手后将此修复合并到同一正式版 5.2.6 / 626。

## 原因与修复

5.2.5 为离屏分类行设置 `resetPending`，跨行 `moveRow` 优先把这类目标行的索引强制设为 0。这将横向滚动复位和遥控焦点选择绑定在一起，即使来源焦点是第 3 张也会落到目标第 1 张。

移除这个强制首项标记。上下仍进入相邻分类，按来源卡片当前屏幕横向中心选择目标行当前可见且中心最近的可聚焦卡片，优先完整显示的卡片；坐标包含两行各自的横向滚动偏移和布局差异。相同宽度与滚动位置的行从第 3 张到第 3 张，已横向翻页或采用不同海报宽度时按屏幕上的实际列对齐。目标布局尚未就绪时才用来源索引并限制到可用项；空行保留原“更多”入口。分类头部“更多”的跨行移动继续对齐目标分类头部入口。

左右逐张移动、首项左键菜单、返回先当前行首项再顶部、轮播与站点的上下顺序保留。完全离屏且没有焦点的分类依然横向回零并清理旧焦点，进入该行时由本次按键确定目标；页面退出复位与手机行为保持。

## 变化范围与交付

本次新增源码变化仅为已有 `CspHomePage`、`CspHomePage$Shelf`、`CspHomePage$TvHomeScroll` 的跨行选择和废弃状态清理，无新增生产类或资源。前次已提交的首次焦点、弹幕设置 smali 挂接与 stable ABI 声明一起交付；原宿主其余代码、数据库、JNI/反射、回移层、原 ZIP/native 资产和双 ABI 门禁保留。

版本保持 stable 5.2.6 / 626，使用 R8 8.8.34 release/full、min-api 23 与 APK 专用固定签名，输出手机/TV、32/64 位四套 APK。旧 625 已保留在撤回内部草稿中。按用户既有要求仅核对源码门禁并直接 GitHub 构建，`run_validation_tests=false`，不运行本地打包或额外回归。遥控视觉路径和安装兼容性由用户真机验收。
