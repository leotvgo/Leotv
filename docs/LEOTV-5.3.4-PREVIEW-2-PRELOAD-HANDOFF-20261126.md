# Leotv 5.3.4-preview.2 / 648 预加载交接修复

用户反馈 647 切集仍然重新加载，并明确要求：打开个性设置的总开关就让所有站点参与预取，不需要单独允许站点。本轮修复与简化按该明确要求执行，继续交付手机/TV、32/64 位四套测试 APK，正式 Latest 保持 5.3.3 / 646。

## 已定位的失效路径

647 的 `PreloadHost.snapshot()` 将原播放器 `q`（当前播放请求头）包含在请求身份里。原 `VideoActivity.A0()` 在包装取链 Callable 前调用 TV `C3/e.v()` / 手机 `F3/f.w()`，其中明确将 `q` 清为 null。即使 `begin()` 保留了下一集响应，`wrap()` 随后的快照也无法匹配它，导致原取链 Callable 再次执行。这是源码可确定的交接缺陷；不是依据加载动画推断。

此外，647 的站点白名单默认关闭，会阻止未单独授权的 CSP/API-4 预取；当前 Result 需要解析、Jx 或包含播放前缀/本地代理时，也会被错误地挡在预取之外。其统一 90 秒 TTL 又会把没有声明到期的响应提前丢弃，影响数分钟后的手动换集。

## 修复后的行为

- 移除“允许预取的站点”窗口、偏好读取和类型分支。保留原总开关（默认关闭）、当前视频缓存和下一集开关；总开关与下一集开关开启后，所有站点按实际相邻剧集参加预取。旧站点偏好不再生效，没有删除用户配置。
- 请求身份改用实际配置、Site 对象、作品/线路/剧集、画质/引擎，以及站点 API/ext/JAR/播放前缀/配置请求头和原生 UA 设置。原播放器对临时 `q` 的清空不会改变身份；修改真实订阅、鉴权或站点仍会拒绝旧结果。
- 稳定播放约 15 秒后预取完整原始 Result。需要解析、播放前缀、内置来源或本地代理的响应也能缓存；不在后台调用全局 Source.stop/fetch。只有实际切集消费时，在原 Callable 的工作线程、会话锁之外执行原 Source.stop/fetch，再交回原控制器；不用重复 playerContent。需要 Web/额外解析的响应仍由原解析器继续处理。
- 允许实际 HTTP 本地代理和直接播放前缀进入 Exo 媒体缓存。缓存下载请求头使用原 TV/手机 UA 规范化方法，避免后台与实际播放使用不同默认 UA。当前视频媒体源取实际打开的 `player.D/q/A/F`，而非仍然需要解析的原始 Result。
- 无明确到期时间的响应在当前会话内保留，最多两小时；已知绝对到期和 AWS 签名到期仍提前 15 秒拒绝。刷新、换源/画质/引擎、退出和缓存清理的隔离保持。首次起播失败继续走一次原取链回退。
- 片尾最后 60 秒对仍有效的下一集地址再补热媒体缓存，过期响应按原片尾规则额外取一次；当前缓存任务按最近一次下一集媒体启动时间让路，避免立即取消片尾补热任务。

补充无 URL/凭据的阶段日志用于确认完整响应是否预取、消费和媒体缓存完成。原播放器准备、首帧及需要的原解析仍会显示其正常加载状态；本轮不以隐藏动画冒充播放器或解码器已经复用。

## 变化与验证

仅修改自有 `PreloadHost / PreloadSettings / PreloadPolicy / VideoPreload / ExoMediaPreload`、版本标识、门禁与说明。原宿主五项允许变更的钩子/构造与 647 相同；未新增宿主重写、播放器库、native 资源、数据库或 JNI/反射 ABI 变化。

源码门禁核对 TV/手机真实的 `v/w` 请求头清空、UA 规范化、Source.stop/fetch、Result/Url/Site 方法及所有精确 Git 路径。CI 新增 `research/check_video_preload_handoff.py`：使用虚构站点和响应编译实际 `VideoPreload / PreloadHost / PreloadSettings / PreloadPolicy`，分别执行 TV/手机的自动预取和原 A0 交接。检查 CSP、API-4、解析响应、本地代理、四分钟后切集、临时请求头清空、真实鉴权变化及 Source.fetch；未变化时原 playerContent Callable 执行次数必须为零。

本地不打包、不运行额外回归；直接 GitHub `run_validation_tests=false`，保留必需源码/针对性交接检查、API23/R8、原样/变化审计与固定签名。实际播放效果由用户真机验收，尤其是开关开启后直接换集、长集片尾、代理/解析来源、字幕/音轨/弹幕和历史。交付结果将在构建/发布完成后记录。
