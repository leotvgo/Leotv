## 详情搜索与 TV 热评

详情页捕获用户入口资源的作品身份，换源只更新播放数据。关键词优先使用本页 TMDB 元数据资源名称，否则使用入口资源名称；后续选中媒体的标题不覆盖它。各站点继续调用原普通全局搜索任务（quick=false、page=1），按完成顺序汇集完整返回结果，不以当前播放标题筛掉菜单结果，不将当前站点替换成单条占位。

首次无可播数据时并行解析匹配候选，采用首个有效播放源后继续异步全局搜索。打开站点菜单复用本页结果；显式重新搜索才开启新一轮，退出详情页关闭任务并释放结果，再次进入重新搜索。已有播放数据、手动选源及原分页目录保持。

豆瓣热评是新增详情模块。TV 上下键明确请求相邻评论卡片焦点，交给已有详情导航滚动显露，解决系统焦点滚动关闭后只能下翻约两条的问题；不移植不存在的原生热评模块。

## 弹幕 API 状态与剧集识别

API 保存、重置时立即刷新原弹幕设置行及手机个性配置的“已配置/未配置”，无需重启。

弹幕身份优先读取原播放器当前 Episode：TV 的 d0()、手机 S 选集适配器的 g 列表和 p() 当前位置；History/初始 Intent 只作缺字段回退。当前集的实际名称和播放地址继续用于请求取消及逐集记忆，保留原记忆键格式。

详情进入全屏播放时携带本页已匹配的作品名称、类型、年份、季数及元数据剧集名称/集数。提示只对相同站点/资源 ID 生效，不另发 TMDB 请求；不携带媒体地址或凭据，剧集数上限 1000，序列化提示超过 128 Ki 字符时省略剧集名称表。名称不带集数时，仅在元数据剧集名称唯一对应的情况下补充季数/集数，不把列表位置当成真实集号。

参考 JAR TitleNormalizer、DanmakuScanner 与 LeoDanmakuService 的识别顺序：优先 API 明确 episodeNumber 与原剧集名称中的中文集/话/期、SxxExx、EP/E；支持分隔符及数字文件名。文件名识别先排除分辨率、编码、声道、年份、文件大小、版本和总集数；多个不同数字无法唯一确定时保持未知。作品名称优先用已匹配元数据，候选匹配同时检查标题、已知季数/年份、综艺日期、加更及上/下后缀，阻止明显无关标题和错误季数接管。

手选记录独立保留本作品的平台和目录，换集后先查已加载目录，再按返回的作品 ID 获取该目录；无作品 ID 的接口仍按原协议请求当前集，仅采用与手选平台/作品一致的返回项。目标缺失时保留手选状态，不回退全局自动匹配；有编号目录无法识别目标时不默认取第一条。本地弹幕仍仅归属当前集，用户主动选择原播放器弹幕仍能接管。

用户明确要求本次不引入弹幕 ID 递增递减。实现仅采用接口实际返回的目录条目及 URL，不推算或构造下一集 comment ID；各接口返回能力和元数据完整度仍限制可识别范围。
