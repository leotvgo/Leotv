# Leotv 5.1.11 手机弹窗与顶栏修正

5.1.10 实机日志显示手机点击 TMDB 配置时调用了不存在的 l4.b(Context) 构造，手机设置新行缺少原生间距；上滑时顶栏控件被重绘，顶部模糊区域过高，切换设置后会残留旧取样。TV 的布局与横屏由用户确认正常。

- 对照四个原 smali：手机 Material 构建器为 o4.b，TV 为 l4.b；手机 l4.b 是 CarouselLayoutManager 辅助类。客户端常量声明各自映射，门禁核对构造、create、继承的标题/视图/按钮/getContext 方法，以及恢复默认所需的参数字段。
- 测试按客户端分目录编译真实的类名关系，手机 l4.b 不再模拟成可用弹窗构建器。手机新设置容器和第二行使用原设置的独立间距，TV 两列保持既有布局。
- 参考 coos-master 的 HomePhoneChrome/HomeGlassChrome：将顶部内容延伸区域与模糊过渡区域分开。手机过渡仅为系统状态栏下方 12dp；内容仍延伸到原顶栏边缘，原控件重绘遵守其实际可见裁切，已折叠的 logo 不再出现。
- 暂停、恢复、取景页、顶栏集合或页面根变化时丢弃上下旧缓冲。暂停状态不重放旧层；透明隐藏的旧页面不参与取景、图像准备和绘制，按当前前景页面查找控件与滚动源。
- TV 顶部区域继续使用既有几何，客户端识别基于 APK 内的 Device.MOBILE，TV APK 装在手机上也按 TV 分支处理。

检查覆盖 API 23/35 的客户端弹窗构造关系、两项设置间距、保存/取消/校验/默认值，以及折叠 logo、窄模糊过渡、暂停清空缓冲和透明旧页替换。四个 APK 由 GitHub 执行 API 23 编译、原样/声明变更审计、固定签名与自动发布；设备效果仍由用户真机复测。实际配置、凭据、数据库和原生库继续保留。
