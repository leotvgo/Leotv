# 5.3.2 / 642：详情与首页海报刷新衔接

用户反馈手机/TV 详情在后续元数据到来时海报闪动，但闪动后仍是同一张图片；要求同时检查首页轮播，并明确详情下方换源不应重新加载海报。继续使用 5.3.2，保留已经验收的加载速度，直接推送 GitHub 构建。

## 定位与修正

- `DetailHero` 旧列表合并分支在当前图片仍存在时也执行 `stopAnimation(false)` 和请求取消。若首张渐显尚未完成，`reveal` 会停在中间值，后续绘制仍会画加载背景。首页独立的合并分支有相同行为。
- 现统一合并详情和首页列表，以原 Slide 对象复用图片身份。当前图片、动画及仍在新列表中的在途请求保持；只取消已经移除的请求。回调以 Slide 在当前列表的索引定位，避免插入/排序后图片与标题错位；首张或替换图的在途请求同样保留。首页其它作品更新为 TMDB 图片时，不因全局图片路线变化而重载未变化的站点海报。
- 非空列表真正替换当前图片或图片配置变化时，保留已显示位图和取色，等新图解码完成后替换。入场渐显仅用于首次无图状态，正常手动/自动轮播仍使用原动画；明确清空列表、关闭页面仍释放图片。
- 原 `bindSource` 无条件加载新站点海报，手动换源重新走整个详情入口，自动换源也取消元数据任务并重新绑定海报。现手动/自动换源只解析并绑定新线路、选集、排序和续播，保留当前元数据和其在途任务。播放来源请求使用独立代次防止旧来源回写；图片刷新使用首次绑定的 fallback，避免滚动/恢复时再切到新站点图片。已完成元数据继续按新播放来源同步追更、收藏与缓存关联。

## 允许变化与边界

生产 Java 仅改变 `DetailHero`、`DetailActivity`、`TvDetailPage` 三份已有源码，新增状态与私有方法均在既有程序类准入下编译。其余 99 份 runtime 源码与已交付 641 逐字节相同，含两端主题高度、TV 焦点滚动、元数据并发、预取、DNS、连接池、持久缓存、500MB 上限及图片主备策略。清单见 `evidence/leotv-5.3.2-642-artwork-source-scope-20261125.json`。

`check_tmdb_loading.py` 在必须源码门禁中加入同图动画/请求保留、重排回调索引、首次渐显条件、换源不重新调用元数据入口及 fallback 固定检查。保留原宿主 smali、资源、数据库 schema/migration、JAR/JNI/反射 ABI、Android 6 回移层和两个 ABI 原生 ZIP 资产。

版本名 **5.3.2**，内部版本码 **642**，固定 APK 证书覆盖升级。只执行必需源码与精确范围检查；GitHub `run_validation_tests=false`，保留 API23/R8 release/full、原样/变化审计和固定签名核对，不做本地 APK 打包或额外回归。换源按同作品处理，主动 TMDB 重匹配和图片设置变化仍生效。首次加载、补充资料、轮播与换源的实际逐帧效果由用户真机验收。
