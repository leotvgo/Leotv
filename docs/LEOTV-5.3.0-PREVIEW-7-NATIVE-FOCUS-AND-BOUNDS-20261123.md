# 5.3.0-preview.7 / 619：搜索窗口原生焦点与分类边界

用户真机确认 preview.6 功能正常，要求只继续修正两端搜索 UI：TV 白色高亮边框及黄色文字，手机黑色边框及原生蓝色文字，并处理截图中的分类按钮溢出。

## 原生状态样式

搜索窗口读取原 `layout/adapter_danmaku` 的 ColorStateList。TV 对应 `color/text`，手机对应 `color/control`；启用/激活状态的颜色用于搜索窗口高亮，正常文字读取原默认色。TV 高亮背景直接借用原 `drawable/shape_item_focused`，保留原白色描边、厚度、圆角与底色。手机保留原 `shape_accent` 涟漪和底色，并按用户明确要求叠加黑色高亮描边。

搜索、排序、接口设置、来源分类、作品分组、剧集和 TV 二维码图标统一使用状态 Drawable 与颜色列表。焦点、激活、选择和按下时自动切换，失去高亮状态后恢复原默认文字；来源、展开分组和当前剧集分别设置 activated 状态。输入框保留 TV 确认后才调用输入法与扫码回填，手机保留触摸输入。没有改变原播放菜单或弹幕协议。

原资源 XML 和来源 SHA256 记录在 `evidence/leotv-danmaku-native-focus-resources-20261123.json`。原 ZIP 资源没有被修改，沿用前版的保护审计。

## 分类和内容边界

之前来源按钮固定 36dp，而父滚动行固定 34dp，截图中的上下描边因此被裁掉。来源行现在按 36dp 子容器和上下各 4dp 留白测量，高亮完整容纳在 44dp 范围内；水平滚动与分类容器都开启边界裁剪。长来源名称保持单行、省略末尾，宽度限制在窗口内；作品分组也限制在自身边界内。

结果区按 ScrollView 的实际宽度计算列数与单元尺寸，布局宽度变化时重新排列，并按原焦点项标签恢复焦点。网格开启裁剪，避免初次布局或窗口调整时用旧宽度画出容器。标题、输入和分类继续固定，选集继续独立滚动。
