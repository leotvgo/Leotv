## APK 追更

详情自动找源会改变 site/id。原 FollowStore 只按 site@@@id 查找，同一已匹配作品从另一播放来源重新进入时找不到记录；按钮读取状态和添加写入由不同判断路径管理。

APK FollowStore 保留原 JSON schema 和 leo_following/entries，同资源键或已匹配的 tmdb_type+tmdb_id 均视作同一影视作品。读取原始记录用于会员判断，日历列表按同一规则合并旧重复，保留原添加时间并使用已有元数据；修改操作将去重结果写回。元数据恢复时幂等补充已有记录，避免监听通知导致反复写入。

详情每次绑定、渲染及 resume 都从同一库查当前作品，点亮/标签/无障碍说明同步；点击直接在 APK 同一库执行添加或取消，取消清除对应作品旧别名。不再让旧 JAR 的精确源键 toggle 作为 APK 的另一个写入口；JAR 共用这份偏好库及变化通知，元数据/播放器桥保留。不同媒体类型的相同数值 TMDB ID 不混为一条，无匹配作品时仍需先获得可靠资料。

本轮没有编辑 coos 的 FollowStore 或 LeotvIntegration。V6 当前构建仅改顶部/底部等待背景与取景路径，与上述 APK 逻辑分开。
