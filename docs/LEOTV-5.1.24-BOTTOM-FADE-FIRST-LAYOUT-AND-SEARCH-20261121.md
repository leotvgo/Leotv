# Leotv 5.1.24 / 534：底栏、首帧与全局搜索

用户真机确认 5.1.23 的选集操作、元数据完成前的宿主背景均符合预期；底栏切直播/设置的长条闪动、手机安装 TV 包时的详情布局翻转和播放空背景仍需修复。本次按用户要求改完后直接推送编译，设备验收交由用户进行。

## 手机底栏

手机的 Portal 不再调用底部 Band，不再抓取滚动内容、处理底部模糊 Bitmap，也不再回放底栏按钮。原 BottomNavigationView 继续由原生父容器绘制一次，背景/tint/阴影继续使用现有透明设置。

新增轻量 BottomFade，作为原 RelativeLayout 中位于导航之前的兄弟 View，底端对齐原导航，起点为导航上方 24dp。它只绘制当前 JAR 的共享背景并使用渐变 alpha，让原生内容淡出到同一个背景；按钮位置、adapter 与触摸保持原样。坐标直接由内容层级转换，不依赖新 View 尚未更新的屏幕位置，也不使用纯色替代宿主背景。

切换直播/设置、打开追更、暂停和离开主页时移除这一 View。TV 原有上下栏效果保留。此项不改动已验收的详情加载背景缓存。

## TV 首帧布局

TV ThemeLayout 在尚未量到内容尺寸时按横屏尺寸初始化。详情页发现实际尺寸改变并请求重新布局时，不再把旧的测量结果绘制一帧；等待实际横屏窗口与本次布局一致后再绘制。等待期间仍保持已保存的宿主加载背景。

播放器在原全屏初始化后注册一次首帧检查：实际窗口须为横屏、video 必须占满原父容器、布局请求须完成。旧预览尺寸只触发原视图的全屏布局，不绘制空的中间帧；原生错误状态允许原错误 UI 正常显示。监听在首帧通过或 View 离开窗口时移除。没有新增截图、蒙层、淡入动画或等待计时器。

资源入口同时去掉已有 Activity 上不必要的 NEW_TASK，保持来源窗口/任务上下文与 URI 授权。Manifest 固定横屏声明继续使用 5.1.23 的设置。

## 个性设置：全局搜索

新入口名称为“全局搜索”，默认关闭，点击直接开启，再次点击关闭；摘要同步显示“开启/关闭”。沿用现有原生行样式，TV 的详情主题/TMDB 两列继续保留，新开关放在下一行的第一列，不另开选择弹窗。

对原宿主支持的 `msearch:标题` 搜索资源，关闭时直接打开详情，以原资源 key/id/name/pic 构造元数据种子，在详情内部并行找源；开启时恢复手机 SearchActivity、TV CollectActivity 的原全局搜索入口。正常可播放资源、手动点击首页/TV 搜索按钮、在原搜索页输入关键词的路径不经过这个资源开关。

自动解析每个线路一次只占一个并发槽位，避免某线路多个较慢候选占满全部解析槽。只有详情返回确实含线路/剧集、标题年份类型/季数符合目标时才采用，第一个完成有效解析的线路优先；使用已加载的原生 Result，保留详情原播放操作。

## 变化与验证范围

新增 WindowLayout 已加入 runtime-sources 清单；新增的代码仍限制在 Leotv 自有类，原 smali 编辑清单保持不变。原生门禁补充检查目标搜索 Activity 与 TV ProgressLayout 状态字段。

定向检查覆盖底部无模糊缓存/无内容重复绘制、先释放后进入原导航、共享背景像素位置、实际全屏首帧与错误 UI、资源搜索路由和较快可播放线路选择。检查中发现的背景坐标及首帧等待阶段的背景保持已修正。按用户要求不跑整套回归或等待 GitHub 编译完成，签名后实际画面由用户新包验收。
